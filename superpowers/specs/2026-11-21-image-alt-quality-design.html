图片 alt 质量补全设计 ​

状态：已批准

日期：2026-11-21
相关：README「待治理的内容问题」MD045；不触及掘金居中 HTML <img> 结构（另项暂缓）

1. 问题（非技术表述） ​

站点里绝大多数图能正常显示。缺的是图的「文字说明」（Markdown 里的 alt）：读屏软件读到空说明时，只能说「图片」，听不出图里是什么。

这不是丢图，主要是 EPUB / 掘金等书源迁移时原稿就没写说明，导入脚本原样保留了空 alt。

规模（2026-11-21 扫描）：约 1617 处空 alt / 436 文件；本地图路径均可解析到文件；约 619 处为外链图。

2. 目标与成功标准 ​

目标： 质量优先，给读者（尤其读屏）可用的短中文说明；普通视觉阅读几乎无感。

成功标准：

  • 处理过的书：![]( 空 alt 清零；图仍能显示；抽检说明与图意相符。
  • 先试点 3 本定 SOP，再按 SOP 分批全站；不以「一次全自动灌假 alt」交差。
  • SOP 跑通并抽检合格前：不全站启用 markdownlint MD045（避免历史债堵 CI）。
  • 全站扫完后再评估：启用 MD045、更新 README TODO 计数与状态。

3. 非目标（本阶段不做） ​

  • 不治理掘金源 <p align=center><img> 居中 HTML（README 已记暂缓）。
  • 不批量用文件名（如 image-002）冒充语义 alt。
  • 不改图片文件本身、不改版式、不换图源（除非原链接已失效且另立项）。
  • 不把「上下文启发式自动填」当作最终质量标准（仅可作草稿辅助）。

4. 策略 ​

试点精修 → 沉淀 SOP → 分批全站。

阶段做什么
P0 试点精修 3 本不同类型，验证写说明的质量条与工作量
P1 SOP把检查清单、文案约定、验收命令写成可复用流程
P2 分批按空 alt 数量从少到多处理其余书；每书一 PR
P3 收尾全站清零后评估开 MD045；更新 README / lint 配置

5. 试点书目 ​

slug书名倾向约空 alt覆盖类型
typescript-introTypeScript 入门教程~21技术小册，体量小，适合首本
docker-guideDocker 实践指南~54掘金类外链图 + 「如下图」上下文多
attached关系的重建~40EPUB 本地 _assets 插图

大户（如 yan-tie-lun ~442、claude-code-dev ~161）放在 SOP 稳定后处理。

6. 单图质量条（写 alt 时遵守） ​

  1. 看图 + 看前后文，写一句中文，约 8–30 字，说明图传达的信息（图表主题、截图界面、示意图关系等）。
  2. 装饰图（重复花边、无信息内容、同一装饰资源反复出现）：统一用约定文案 装饰图，不强行编造情节。
  3. 禁止：空 alt；纯文件名；与图无关的套话；把整段正文复制进 alt。
  4. 外链图：只补 alt，不改为本地（除非链接失效另案处理）。
  5. 语法：在空的方括号里填上说明文字，圆括号里的路径保持原样不动。

7. SOP 大纲（P1 落成独立文档） ​

试点通过后，写成例如 docs/superpowers/specs/image-alt-sop.md（或 docs/ 下维护文档），至少包含：

  1. 列清单：对该 slug 扫出所有 ![](。
  2. 逐张补全：打开图（本地文件或外链）+ 上下文，按质量条写 alt。
  3. 装饰图规则：套用「装饰图」约定。
  4. 自检：
    • rg '!\[\]\(' docs/books/<slug> 无命中；
    • 抽若干章节确认图仍显示、说明合理；
    • 不引入 markdownlint 格式债（必要时 npm run lint:fix 仅限改动文件）。
  5. 提交：分支 docs/alt-<slug>；提交说明 docs: 补全《书名》图片 alt（slug）；开 PR。
  6. 进度：维护一张「已完成 slug」列表（可放在 SOP 文末），避免重复劳动。

8. 工具与自动化边界 ​

  • 允许：脚本生成「待办清单」（文件:行号:路径）；--dry-run 统计；可选「上下文草稿」供人工改。
  • 不允许：无审阅的全站自动写回；用文件名批量填 alt 后宣称完成。
  • 试点阶段以 Agent 看图（Read 本地图 / 打开外链上下文）+ 人工抽检为主；SOP 稳定后再考虑轻量辅助脚本。

9. 对读者体验的影响 ​

  • 视觉：几乎不变（只改 Markdown alt 文本）。
  • 读屏：说明从无到有，体验变好。
  • 风险：写错 alt 会误导读屏用户 → 靠质量条与抽检控制；发现错误按书热修。

10. 验收（每个 PR） ​

  • [ ] 该书空 alt 为 0
  • [ ] 抽检 ≥3 张：说明与图意一致（或确认为「装饰图」）
  • [ ] 未改无关书籍；路径未被改坏
  • [ ] PR 说明含 slug 与处理数量

11. 开放问题（审阅时确认） ​

无阻塞项。已确认：质量优先、全站分批、先试点三本再 SOP。
